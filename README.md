# for-ai-website

ChatGPT が小さな Web サイトを作り、レビューと改善を繰り返していくための公開リポジトリです。

## 現在のサイト: ONE

「今日やる一つだけ」を決めて、短い集中スプリントを始める Web アプリです。アカウント登録は不要で、タスクや集中記録をサーバーへ送信しません。

## 使い方

1. 「いま一番進めたいこと」にタスクを入力します。上限は120文字です。
2. 10 / 25 / 50分、または1〜180分の整数で集中時間を選びます。
3. スタートし、必要に応じて一時停止・再開します。
4. 0:00まで完了したら「この集中を記録する」か「記録せず破棄する」を選びます。

未記録の完了がある間は、次の開始・リセット・時間変更をロックします。記録は完了した集中ごとに1回で、翌日に記録しても実際に完了した日の回数へ加算します。

### タイマーと表示

- 実行中・一時停止中・未記録完了の状態を保存し、再読み込み後に復元します。
- 残り時間に加え、集中時間全体の進捗バーを表示します。
- 実行中だけ終了予定時刻を表示します。日付をまたぐ場合は月日も表示し、再開時は新しい終了時刻へ更新します。
- タブのタイトルにも実行中の残り時間・一時停止・未記録完了を反映します。
- 集中表示ではタスクとタイマーを大きく表示します。完了時は記録操作が見える通常表示へ戻ります。
- 表示テーマは「自動 / ライト / ダーク」の3択です。自動では端末設定に追従します。
- モバイル表示、キーボード操作、スクリーンリーダーに対応するための表示・読み上げ設定を用意しています。

| キー | 操作 |
| --- | --- |
| Space | 開始 / 一時停止 |
| F | 集中表示の切り替え |
| Escape | 集中表示を解除 |
| タスク入力中の⌘/Ctrl + Enter | 開始 / 一時停止 |
| 自由設定・今日の目標の入力中のEnter | 入力値を設定 |

文字入力中やボタン操作中はグローバルショートカットを発火させず、IME変換中のEnterも確定操作から除外します。カウントダウンを毎秒読み上げる設計にはせず、状態変化を中心に通知します。

### 完了音・完了通知・画面維持

いずれも初期設定はOFFです。対応ブラウザで利用者が明示的にONにした場合に利用します。

| 機能 | 動作と権限 |
| --- | --- |
| 完了音 | Web Audioで短い2音をブラウザ内で生成します。ON操作時に試聴音を鳴らし、外部音源・マイク・通知権限は使いません。 |
| 完了通知 | ON操作時にブラウザの通知許可を確認します。許可済みでタブが背景にあるときだけ通知し、本文にタスク内容を含めません。 |
| 画面維持 | Screen Wake Lockで、実行中かつ表示中のタブだけ画面スリープを抑えます。一時停止・完了・非表示・ページ離脱時に解放します。 |

タブへ戻ると古い完了通知を整理し、通知権限を再確認します。非対応・権限拒否・音声再生制限などがある場合は案内を表示し、タイマー本体の利用は続けられます。

### 集中記録と今日の目標

- 「今日 / 今週 / 連続日 / 累計」を表示します。今週は月曜日から今日までの合計です。
- 今日が未実施なら、連続日数は昨日までの連続を保持します。保存履歴90日分すべてが連続する場合は `90+` と表示します。
- 直近7日の棒グラフと、直近30日のアクティビティマップ・合計回数・活動日数を表示します。
- 日次履歴は最大90日分を保存します。週間統計や30日マップはその履歴から計算し、別の追跡データは保存しません。
- 「今日の目標」は1〜12回で任意設定でき、残り回数・達成状況・進捗バーを表示します。目標を超えてもバーは100%にとどめ、読み上げには実際の回数を含めます。
- 目標はその日だけ有効で、翌日は解除します。期限切れ・不正な保存値の掃除では、別タブが更新した値を誤って消さないよう照合します。

タスク本文の履歴は残しません。翌日は前日のタスクを持ち越さず、進行中・一時停止中・未記録の集中がある場合だけ、その1回が終わるまで保持します。

## 保存・バックアップ・削除

### ブラウザ内の保存

タスク、タイマー、集中回数・日次履歴、今日の目標、表示・通知・画面維持の設定、復元取り消し用データ、タブ間調停用の値を `localStorage` に保存します。同じブラウザ・同じオリジンのタブ間では更新を同期します。

保存状態を画面上部に表示し、利用中の読み書き失敗も通知します。表示テーマ・完了音・通知・画面維持・今日の目標の保存結果は読み戻して確認し、失敗時は現在タブへの反映と端末への保存を区別して案内します。

保存障害時は、そのタブに残る入力や進捗を保持して利用を継続します。再読み込み前に、検証できた現在タブの累計・日次履歴・タイマー時間を「JSONを書き出す」で救出できます。安全な書き戻しを確認できない間は、復元と取り消しを無効化します。

### JSONバックアップ

| 含めるデータ | 含めないデータ |
| --- | --- |
| 累計回数、最大90日分の日次履歴、選択中のタイマー時間 | タスク本文、実行中・一時停止中・未記録完了のタイマー、タブ間セッションID、今日の目標、表示・通知・画面維持などのUI設定 |

- 書き出し・読み込みはブラウザ内だけで完結します。
- 復元するファイルは100KB以下で、既知の形式・キー・正しい日付・回数・1〜180分の時間だけを受け付けます。累計が履歴合計より小さいなどの矛盾は拒否します。
- 復元はこのタブと別タブのアクティブなタイマーを確認し、完全に停止している場合だけ許可します。
- 復元直前に内容を確認し、確認中に別タブで記録が更新された場合は中止します。
- 復元前の状態を1世代だけ退避します。復元後の記録・時間設定が変わっていない間は、再読み込み後も「直前の復元を取り消す」を利用できます。
- 保存確認に失敗した復元では、可能な範囲で直前の状態と以前の取り消し情報を戻します。

### データ削除

「この端末のデータを削除」は2段階で確認し、ONEが使用する既知の保存キーだけを削除します。`localStorage.clear()` は使わず、同じオリジンの無関係なデータには触れません。別タブにも削除を通知します。

ダウンロード済みのJSONファイルは削除対象外です。ブラウザ側の通知許可も、ブラウザの設定で管理します。

## セキュリティと実装上の前提

- 静的HTML / CSS / JavaScriptのみで、ビルド・外部依存・外部API・解析ツール・Cookieは不要です。
- CSPは `default-src 'none'` を基本にローカルのJavaScriptとCSSだけを許可します。外部通信・画像・フォーム送信・iframe・workerなどは許可しません。
- ユーザー由来の値を `innerHTML` などでHTMLとして挿入せず、安全なDOM操作で表示します。
- タイマー保存値のサイズ・型・日付・状態の整合性は、`timer-bootstrap.js` の共通検証器で確認します。旧形式の完了状態との互換性も維持します。
- 集中の記録は、未処理完了の消費を保存確認してから、累計・日次履歴を順に保存確認します。
- タブ間のセッションIDは認証情報ではなく、集中1回の識別用です。新規IDにはWeb Cryptoを使います。
- 通常のタブ間調停はlocalStorageによる照合であり、完全な原子的ロックではありません。完了音・通知の重複抑制には、利用可能ならWeb Locksを使い、非対応時は保存値の再確認へ切り替えます。

### ファイルの役割

| ファイル | 主な役割 |
| --- | --- |
| `index.html` / `styles.css` / `timer-progress.css` | 画面、読み込み順、CSP、表示テーマ |
| `timer-bootstrap.js` | タイマー保存値の共通検証、起動前の時間復元 |
| `app.js` | 基本タイマー、日付・タスク・履歴、共通の保存処理 |
| `stats.js` / `daily-goal-progress.js` | 統計、日次目標、目標の進捗バー |
| `tab-guard.js` | セッション照合、完了記録の段階保存、待機中の時間同期 |
| `custom-timer.js` | 自由設定、タイマー進捗、終了予定時刻、タブタイトル |
| `backup.js` / `privacy-reset.js` | JSON入出力、復元取り消し、ONEデータ削除 |
| `storage-status.js` | 保存警告、タスクの文字数・別タブ同期 |
| `completion-sound.js` / `wake-lock.js` | 完了音・通知の制御、画面維持 |
| `theme-bootstrap.js` / `theme.js` / `shortcuts.js` | 描画前テーマ復元、テーマ操作、ショートカット |
| `scripts/` / `.github/workflows/quality.yml` | 動作・静的検査とGitHub Actions |

各JavaScriptは共通状態や既存関数の拡張を通じて連携するため、`index.html` の読み込み順が重要です。テーマの初期復元はCSSより前、それ以外は定められた順序で `defer` 実行します。

## ローカルで確認する

`index.html` をブラウザで開くか、リポジトリのルートで次を実行して `http://127.0.0.1:8000` を開きます。ローカルサーバーは自分の端末からだけ接続できるようにします。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

保存先はオリジンごとに異なるため、直接ファイルを開いた場合とローカルサーバー経由では記録が別になることがあります。必要な記録はJSONバックアップで移してください。通知や画面維持の利用可否はブラウザ・権限・実行環境によって異なります。

### 検査

Node.jsとPython 3の標準ライブラリを使います。依存パッケージのインストールは不要です。

```sh
set -e
for script in *.js scripts/*.js; do
  node --check "$script"
done
for check in scripts/*_checks.py; do
  python3 "$check"
done
for check in scripts/*_behavior_checks.js; do
  node "$check"
done
```

GitHub Actionsではこれらに加えて代表的な秘密情報パターンも検査します。Actionsの権限は `contents: read` のみ、checkoutは不変SHAへ固定し、認証情報を作業ディレクトリへ保持しません。

Pythonの検査は主にHTML解析やソースコードの静的検査です。CIの成功だけでブラウザ全体の動作を保証するものではないため、変更した機能は実際の操作経路でも確認してください。
